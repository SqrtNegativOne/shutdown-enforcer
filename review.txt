  - setup.pyw:147 — The "give up" hours logic has a subtle edge case. now < parse_time(GIVE_UP_BEFORE) (before 05:00) and now > parse_time(GIVE_UP_AFTER)
  (after 23:30) — but SHUTDOWN is at 23:50, which is after GIVE_UP_AFTER. So if you run setup between 23:30 and 23:50, it bails out even though the shutdown

  - setup.pyw:125 — psutil.Process().username() — this gets the username of the current process. If setup is run as a different user than expected (e.g.,

  - setup.pyw:162 — The notification message args use double quotes inside a string that's itself part of a command string: f'"Closure in {closure_diff}
  minutes..."'. This works, but if APP_CLOSURE or the diff ever contain special characters, it could break. Low risk with the current hardcoded values, but
  fragile.

  close.pyw — window killer

  - close.pyw:32-36 — There's a subtle scoping bug: window_title is assigned inside the try block, but proc is also used on line 32 outside any guard. If
  GetWindowText raises (unlikely but possible), window_title would be unset when referenced in the log on line 32. More importantly, proc is referenced on
  line 32 but defined inside the try block starting on line 19 — if an exception is raised before line 19 completes, proc could be undefined when the log
  line runs. This is fine in practice since both assignments are before line 32, but the structure is a little fragile.
  - close.pyw:40 — notif(...) with ms=3000 is called before EnumWindows. The notification window itself is a visible window, and EnumWindows is called while
   it's still running (since notif blocks via mainloop for 3 seconds). The notification window will be in the enumeration and PostMessage(WM_CLOSE) will be
  sent to it too — though it will likely just close it early, which is probably fine.

  General

  - No __init__.py in src/, so the relative imports (from utils import logger) rely on the working directory or sys.path being set correctly. Works when run

  ★ Insight ─────────────────────────────────────
  - schtasks /ru USER /rl HIGHEST schedules a task at highest privilege under a specific user — this is the correct Windows API pattern for running elevated
   scheduled tasks without a UAC prompt at runtime, since the privilege level is baked in at creation time (which is why setup.pyw itself must be run as
  admin).
  - PostMessage(hwnd, 0x0010, 0, 0) sends WM_CLOSE rather than forcibly killing the process — this is the "polite" way to close windows, giving apps a
  chance to save/prompt, unlike TerminateProcess. Apps can still ignore or veto it.
